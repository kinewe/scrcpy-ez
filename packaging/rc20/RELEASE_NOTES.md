# scrcpy-ez 2.4.2-rc.20

基于 RC.19 的正式后续版本。双通道渲染成为默认路径，启动流程全自动。2026-10-28 已由用户实机验收（速度、界面、自动化均通过）。

- 双通道渲染默认开启：原生 PNG 背景/静态 UI + 实时键控动态区，配合 `--perspective-camera` 自动启用；无需实验环境变量，也不再需要外部 `collect.py` 采集脚本。
- 全自动设备端探针：客户端进入透视相机后自行拉起设备端探针，并推送独立副本到 `/data/local/tmp/ez-native-ui-probe.jar`（本 fork 的 CleanUp 会立即删除 server jar，因此使用专用副本），自动定位扫码页面。探针失败、设备不支持或不匹配时自动回退单键路径，不影响普通投屏。
- 自适应预热：学习在第一个原生帧即开始，默认 3.5 秒自适应、不少于 6 帧、支持区域 900 毫秒稳定即冻结；首个区域清单在第 10 帧后完成（快速窗口，无需 DUMP）。
- 合成细节：受保护组件按 min-alpha 清理；compose 阶段做纯颜色残差抑制（diff.a < 0.012 不贡献颜色）。
- 校准遮罩保持到实时合成就绪，再快速淡出。
- 启动速度（实测）：从进入扫一扫到校准遮罩完成淡出约 **5.0 秒**（低分辨率布局 576x1280/240）；高分辨率布局约 6.0 秒；RC.19 时代人工 `collect.py` 流程约 20.5 秒。
- 本轮验收采用的低分辨率布局参数：`SCEZ_VD_AUTO_DPI=0`、`SCEZ_VD_PRESERVE_UI=0`，应用以 576x1280/240 布局，原生 PNG 采集由 1440x3200（约 320 ms/帧）降到 576x1280（约 100 ms/帧）；UI 布局经用户确认正常。
- Windows 启动器、原生客户端和 Android server 版本统一升级为 RC.20（`2.4.2-rc.20` / `5.0.1-ez2.4.2-rc.20`）。
- 需要对比或回退时，可用 `SCEZ_NATIVE_UI_AUTO=0` 临时关闭自动双通道（实验用环境变量保留）。

**已知限制（已接受，继续跟踪）：** 静态 UI 组件附近仍会残留轻微、固定位置/周期性的蓝色残影（视频色度噪声类）。不影响本轮验收；RC.20 不宣称消除该现象，后续版本继续跟踪。

历史 RC.19 的 emulator 灰卡修复、RC.18 的透视校准/flex/省电逻辑均继承。完整变更与验证状态见 `TEST_REPORT.md`（发布目录内）与 `packaging/rc20/TEST_REPORT.md`。

### 便携包修正（2026-10-28）

- 透视会话保留 GUI 设定的虚拟屏分辨率/DPI；仅注入绿键、preserve-ui=0、auto-dpi=0、IME local 与无装饰/保留内容参数。
- 设备探针日志并入客户端投屏日志（`NATIVE_UI device:` 前缀），不再弹出额外控制台窗口。
- 相机 PNG 分辨率 = 应用逻辑画布 = GUI 设定分辨率（AOSP CAPTURE 无缩放参数）；启动时间随设定分辨率变化。
