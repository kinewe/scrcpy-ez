# scrcpy-ez 2.4.2-rc.21（候选草稿，待实机确认）

基于 RC.20 验收版本的后续候选。核心变化是把启动预热改为**渐进式快速启动**，并统一透视会话的日志输出与按键注入。

- **渐进式快速启动预热**：约 1.2 秒 / 4 帧即冻结首层（快速可用），随后在后台做 min-alpha 精修；不再需要等待完整预热结束才可用。启动目标约 **5 秒**（flex 逻辑画布 1440x3200 / 客户端窗口 576x1280/240，原生 PNG 采集为 1440x3200；RC.20 同条件约 6 秒）。
- **按应用自动选择透视键色**：客户端根据 `--start-app` 自动选择键色——企业微信（`com.tencent.wework`）→ green（其扫描光为蓝色）、微信（`com.tencent.mm`）→ 生产默认蓝键（其扫描线为绿色）、未知应用 → 蓝键；仅在未显式设置 `SCEZ_PERSPECTIVE_KEY_COLOR` 时生效。GUI 启动脚本不再注入绿色键。
- **微信扫码页支持**：设备端探针的扫码窗口匹配扩展到目标包（企微/微信均自动定位扫码页），不再只绑定企业微信。
- **保持 GUI 已配置的分辨率/DPI/flex 不变**：不再依赖低分辨率布局或关闭 DPI 的绕行。
- **探针日志统一**：设备端探针日志并入投屏日志（`NATIVE_UI device:` 前缀），不再出现独立控制台/日志窗口，便于用户与支持排查。
- 继承 RC.20：双通道渲染默认开启（原生 PNG 背景/静态 UI + 实时键控动态区）、设备端探针全自动（无需 `collect.py`）、校准遮罩保持到实时合成就绪、自适应预热与 min-alpha 清理、compose 阶段颜色残差抑制（diff.a < 0.012 不贡献颜色）。
- Windows 启动器、原生客户端和 Android server 版本统一升级为 RC.21（`2.4.2-rc.21` / `5.0.1-ez2.4.2-rc.21`）。
- 需要对比或回退时，可用 `SCEZ_NATIVE_UI_AUTO=0` 临时关闭自动双通道（实验用环境变量保留）。

**已知限制（继续跟踪）：** RC.20 记录过的轻微、固定位置/周期性蓝色残影（视频色度噪声类）在 RC.21 不宣称消除，后续版本继续跟踪。

**状态说明（候选草稿）：** 本文为 RC.21 候选文档。候选构建（`build-rc21.py`）与实机验证待 Lead 发出 “integration ready” 后执行；完整发布打包与发布验证在实机确认后执行。RC.20 的验收记录与发布文档保存在 `packaging/rc20/`。
