# 音墨 v2.2.2-root.2：root 用户尝试版

这是一次没有 root 实机验证的修复尝试，面向“上传 `/data/local/tmp/scrcpy-server.jar` 被拒绝”的问题。不保证解决所有 root 模块、ROM 或 SELinux 策略异常。

## 使用方法

1. 将 ZIP 解压到独立的 `yinmo-2.2.2-root.2` 文件夹，不覆盖 ez 2.2.2 或音墨 2.2.16r2，也不要将尝试版 EXE 单独复制进正式版。
2. 打开此文件夹的 `scrcpy-ez.exe`，确认窗口显示 **scrcpy-ez**，版本为 **v2.2.2-root.2**。首次尝试建议使用 USB。
3. 按原流程授权 USB 调试并开始投屏。支持独立 BAT、主投屏、应用窗口及 USB／无线切换。
4. 正常 ADB 上传通过时，不调用 `su`。失败时，请保持手机解锁，在 root 管理器中允许 **Shell / ADB shell（uid 2000）** 的授权；等待授权最多 **3 分钟**。修复全过程包含同设备排队，最多约 **5 分钟**。这是电脑程序的超时设置；手机管理器若自行超时或主动拒绝，仍会提前停止。
5. 拒绝或未授权会停止本次尝试。先检查手机的 root 管理器，再点击重新投屏。即使电脑端已允许所有权限，手机的 root 授权仍由手机管理器决定。

KernelSU、APatch 或隐藏 root 的模块可能让 Shell 看不到 `su`。需要在相应管理器中允许 Shell 获取 root；电脑程序无法代替手机授权。已通过其他方式让 adbd 以 uid 0 运行的设备，会使用已有权限，不执行 `adb root`。

## 它会做什么

先核对具体连接的物理序列号，再读取目录与现有 JAR 的元数据，并使用随机小文件验证普通 `adb push`。

如果上传不通且路径检查通过，按顺序尝试：

- 使用设备自身 `restorecon -F` 恢复目录和现有 JAR 的标签，不递归遍历。
- 仍失败且标签恰为通用 `system_data_file:s0` 时，尝试将相关路径临时设为 AOSP 的 `shell_data_file:s0`；不覆盖任意 OEM 标签或 MLS 分类标签。
- 仍失败且已确认 `shell_data_file:s0` 时，将目录属主／属组设为 `2000:2000`、权限设为 `0771`；现有普通 JAR 使用 `2000:2000` 和 `0644`。

每步均复检普通 ADB，通过就停止修复并启动基线 scrcpy。不会删除原服务端 JAR、清空 tmp、递归改属主、关闭 SELinux、修改 root 模块、开启新 root 服务或重启 adbd。常规 scrcpy 仍有它原本的上传和服务端清理行为。

目录或 JAR 为符号链接、JAR 有多个硬链接、目录不存在、身份核对失败、root 与 Shell 的目录 inode 不一致时，停止自动修复。用户停止投屏、退出软件或当前连接消失时，会取消检查；修复完成前不会启动客户端。

## 如何反馈

保留 `root-repair-logs` 内最新的 `before-*.json` 和 `root-*.json`，以及界面原始输出。目录不可写时，日志回退到 `%APPDATA%\yinmo-root-2.2.2\root-repair-logs`。报告包含设备序列号、连接地址、命令、标签、权限和错误信息，分享前可自行遮蔽设备标识。

`healthy` 仅表示启动前普通 ADB 检查通过；`repaired` 仅表示修复后上传探针通过；两者都不等于投屏画面、音频和控制已实机验证。`failed` 表示本次停止，`canceled` 表示用户操作、连接变化或超时中断。

若 root 模块不断改回标签，修复可能只短暂生效。没有对策略规则、只读挂载、文件系统损坏、空间不足或不可变属性进行自动修复。授权失败不会自动换设备或反复弹授权。直接运行裸 `scrcpy.exe` 会绕过此版本的检查，应通过 GUI 或 `投屏支持.bat` 启动。

## 外观与版本标记

本次修订恢复 ez 2.2.2 的主窗口标题、页眉、页脚、托盘和版本弹窗外观，只通过版本号 `v2.2.2-root.2` 区分。前端 HTML、JavaScript、CSS 和图标画面与基线一致；Windows DPI 显示清单也保留原版。root 授权说明及诊断仍记录在原始输出和包内文档中；正式版更新禁用和配置隔离机制保留。

## 版本隔离与撤回

源码分支：[音墨 codex/root-tmp-repair-v2.2.2](https://github.com/kinewe/PC-kinewe-yinmo/tree/codex/root-tmp-repair-v2.2.2)。GUI 和 EXE 产品版本均为 `v2.2.2-root.2`；底层客户端与服务端保持 ez 2.2.2 包中的原配对版本，不改变握手版号。

正式版更新与安装入口已停用，设备档案默认存于此独立解压文件夹，系统配置回退使用独立目录，不导入正式版全局档案。显式环境变量路径覆盖仍由用户自行控制；本次交付不配置任何覆盖变量。

不用此版本时，关闭并移走其独立文件夹即可恢复电脑上的正式版使用。**手机上的目录／文件元数据修改不会随关闭程序自动撤回。** 修改前的值记录在 `before-*.json`；不提供盲目自动回滚，以免恢复已经错误的标签或覆盖之后发生的变化。有需要时应由熟悉该 ROM 的用户根据报告逐项判断。
