## 修改

普通应用窗口在“窗口跟随 + 自动 DPI”的 UI 保留路径中，第一笔尺寸请求立即处理，之后持续请求按 100ms 合并，只保留最新尺寸。期间不断输入不会向后推迟同一批请求的期限，停止拖动后最后一个尺寸仍会处理。回调由单个工作线程串行执行，回调较慢时后续请求继续合并，不并发修改虚拟屏。

不适用上述 UI 保留路径的普通旧模式、透视模式继续使用 300ms 合并，不改主投屏。投屏 FPS、DPI/逻辑画布、等比预览和点击映射策略保持。100ms 是尺寸调度间隔，不是端到端更新时间；不保证没有短暂黑边，也不把视频 FPS 改成 10。

取消会丢弃待处理尺寸，停止会拒绝迟到请求。仍保留原有白名单、目标包解冻和心跳回收实现。

## 用户测试

1. 退出旧 EZ，在本目录运行 `Start-Fast-Resize-Test.cmd`。
2. 浏览器开启“窗口跟随”，DPI 保持自动，连续拖动窗口边缘、改变横竖比例。
3. 对比 preview7 的黑边停留、布局跟随速度、松手后的最终尺寸和画面连续性；留意加快重建后是否更卡顿。
4. 提供 `app-fast-resize-test.log` 和观感。初始化应记录 `SCRCPY_EZ_FLEX_TIMING interval_ms=100 leading=true`；若为 300/false，则走的是旧调度路径。

设备操作由用户进行。本助手仅做代码、构建和电脑本地回归；当前用户体验反馈为未见本质改善，尚无新日志作定量复核。
