# RC23 自动原生 Alpha：能力匹配与档案

## 判断顺序

1. 根据当前应用实际 UID、窗口 token 和非主屏窗口，确认唯一的相机页面。多个候选无法唯一归属时暂不操作。
2. 读取当前 View 结构、相机预览类型、几何及背景，确认所需 API 和恢复条件。TextureView、SurfaceView、系统场景过渡分别按能力选择；不通过应用名、机型、版本或 ROM 白名单决定支持与否。
3. 先试有限的背景/相机 View 操作；普通来源仍不透明且满足场景过渡能力时，执行有界的系统场景尝试。命中成功记录可优先尝试对应路径。
4. 至少两帧逐像素确认非空、具有空间变化的真实 Alpha，并验证相机中央区域透明覆盖。成功后才启用桌面叠加。
5. 持续监听窗口、相机结构和来源修订。来源变化撤销旧画面、重设帧基准并重新验证；不把旧页的补丁应用到新页。
6. 离开页面或正常关闭时恢复属性与系统过渡状态。无法可靠恢复背景或 Surface 层级时，事先要求可验证的子 Activity 恢复路径，并正常结束本次原扫描 Activity。

系统设置组件和框架协议必须在目标机上通过检查。相机页面必须符合当前可验证的布局和恢复条件；这仍不是任意 Android 应用的透明获取保证。失败后退回原有画面，在当前窗口内限制重试。历史失败记录作为诊断信息，不因曾失败或机型/版本不同而禁止新窗口探测。

## profiles.json

沿用 `devices[设备身份].apps[包名].nativeAlpha.recipes[]`。应用条目含 versionName、versionCode、lastUpdateTime；记录还保存签名、SDK、ROM、用户、尺寸/DPI、页面结构、相机类型、有限操作步骤、恢复方式、捕获来源及系统过渡依赖信息。

`engineVersion=7` 的记录使用 texture-background、surface-zalpha 或通用 system-scene 策略。旧 wechat-system-scene 记录可作为迁移候选。缓存不存可直接重放的脚本、临时 View 实例地址或其他设备的窗口 token、UID。

机型、版本与 ROM 是入档参考、诊断信息及缓存来源分类依据，不是运行能力准入条件。即使版本或设备不同，也可以用步骤指导当前探测，但需要重新检查实际窗口、API、恢复条件并验证真实 Alpha。

本轮实际将平板微信 8.0.74 的场景步骤用于 K80 微信 8.0.78：跨设备候选通过现场能力与 Alpha 检查后生效，保存为手机自己的记录；再次进入命中本机记录。UID、窗口和 Surface 来源均重新绑定。

## 响应与边界

当前手机首次跨设备候选接通约 3.26 秒，加速版本机候选约 3.48 秒；其中包含原有几何对齐、微信初始化、系统过渡与源绑定。尚不能保证所有应用秒开。加速改善的是接通后的连续 UI 更新，不能将其等同于入口判断耗时。

同版本的跨设备记录可以提供指导，不能继承另一设备的成功结论。灰度布局、相机类型、多用户、分屏和系统实现都可能不同。反过来，版本不同也不应直接拒绝，只要当前能力与真实输出通过即可。

正常客户端写入自身运行目录 profiles.json；GUI 会话使用 GUI 的 ProfileStore 统一合并。发行 ZIP 排除真实档案和个人设置。旧 RC22 写同一个文件可能丢弃其不认识的字段，所以本原型使用独立运行目录。

强制终止进程、断电、系统调用失败仍有恢复边界。本版通过透明与内容更新检查，不等于已经验收真实二维码识别业务。

## engineVersion 9：独立规则身份与流性能

ruleKey 只描述渲染结构、预览类型、捕获源、有限步骤及恢复方式；设备和版本字段保留在观察档案，不能成为规则准入条件。传给设备的候选模板不包含 environment、application 或既往 FPS。历史失败保留供诊断，运行模板选择只使用不同成功规则。每次仍绑定本机 UID/window/display 并检查能力与原生输出。

recipe.stream 包含 protocol、backend、inputColour/outputColour、alphaExact、rgbaExact、maxRgbError、fallback；取得样本后补充 measured、sampleFrames、sourceFps、readMs/encodeMs/sendMs。透明通过时即可显示，不等待性能采样；后端发生切换会再次入档。A8 精度严格验证，色域转换与原像素复制分别记录。
