# RC.17 preview7：拖动窗口实时预览

版本保持 `2.4.2-rc.17`，FileVersion `2.4.2.1707`，协议 `5.0.1-ez2.4.2-rc.17-preview7`。基于已保存的 layout6 提交 `6f1212f829251189494ad1151be10223566fb986`；旧运行包和远程标签 `ez-2.4.2-rc.17-layout6` 保留。

## 行为

普通 flex 应用窗口在 Windows/macOS 的原生拖动循环中，通过 SDL 的窗口 expose/resize/move 回调继续消费新视频帧并重绘，不必等常规事件循环返回。窗口尺寸暂时领先编码尺寸时，默认显示策略先把已有画面按比例完整放进窗口；新布局和新编码帧到达后继续更新。可能短暂出现黑边，避免把旧帧裁掉或拉伸变形。

默认自动显示策略才启用该临时适配；明确指定 `--render-fit` 时保留用户选择。普通主投屏不启用 flex 预览，透视相机保留已有矩形策略。窗口跟随、layout6 的有效 DPI/逻辑画布和服务端约 300ms 的尺寸合并节奏保持。即时画面预览与 Android 应用实际重新排版是两种更新，不承诺每个显示刷新周期都重建布局或编码器。

本次只进行代码修改和电脑本地测试，没有连接、控制或唤醒 Android 设备。真正的拖动观感、D3D11/OpenGL 路径及点击效果待用户确认。

## 用户测试

1. 退出旧 EZ，在本目录运行 `Start-Resize-Preview-Test.cmd`。
2. 浏览器应用窗口开启“窗口跟随”，DPI 保持自动。
3. 持续拖动窗口边缘，观察画面能否在松手前缩放、滚动动画是否继续；按住边缘暂停移动片刻，也观察视频有无更新。
4. 拉成横向、竖向再放大，检查平板 UI 是否保持、画面边缘有无裁切、松手后点击是否准确。
5. 正常关闭窗口，提供 `app-resize-preview-test.log`，附上实际观感。

新增日志 `SCRCPY_EZ_FLEX_PREVIEW` 最多每秒一条，记录原生窗口回调中的重绘次数、新帧消费次数、窗口/视频尺寸及默认临时适配开关；不记录画面内容、输入文本或点击坐标。layout6 的逻辑画布与 root task 配置日志继续保留。

## 实现与验证范围

- 限制 SDL 回调在主线程、当前窗口、已显示且未重入时访问渲染器。
- 在释放纹理/窗口之前注销事件监听，监听注册移至初始化成功后。
- 丢弃过期的新帧唤醒事件后再消费帧，避免删掉并发到达的新帧唯一唤醒；其他事件不清除。
- 临时预览矩形同时供绘制与点击坐标换算使用。新帧已经绘制时不重复提交；没有新帧或暂停时仅重画已有纹理。
- 原有白名单、目标包解冻、心跳和 layout6 逻辑画布算法未改动。

本地新增无窗口 SDL 事件集成测试与几何/坐标回归，覆盖不轮询时的即时回调、生产线程拒绝、其他窗口/隐藏窗口隔离、重入、注销和队列事件保留；CLI 回归覆盖自动模式、显式显示策略、主屏与透视模式。完整结果见 TEST_REPORT.md 和源码包 engineering/。

依据：[SDL 拖动期间重绘说明](https://wiki.libsdl.org/SDL3/AppFreezeDuringDrag)、[事件监听线程要求](https://wiki.libsdl.org/SDL3/SDL_AddEventWatch)。
