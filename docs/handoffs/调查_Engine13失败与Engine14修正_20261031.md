# Engine 13 实机失败调查与 Engine 14 修正

## 已证实的结果

用户通过 CMD 实测 Steam/向日葵蓝底、支付宝退出、V次元显示物理相机画面。日志分别是 RC23_E13_STEAM-20265、SUNLOGIN-20324、ALIPAY-20043、VDIMENSION-20392。

- 支付宝：scene_window_feature_unavailable 后出现 closed_original_child_activity；本轮首先证实的是机制主动结束扫码 Activity，没有应用进程崩溃的证据，不能归因支付宝自杀/防外挂。零有效 Alpha 帧。
- Steam：getCompositionOrder 不可用、restore_scope_unavailable；此前新增快照分支没有实际获取到原层级，零有效 Alpha 帧。
- 向日葵：resource=false、restore_scope_unavailable；此前主题资源分支未获取到资源，零有效 Alpha 帧。因类名/路径识别失败而拒绝，不是已验证“原生 Alpha 不可能”。
- V次元：虚拟相机创建成功，但没有 stream 或 PERSPECTIVE_ACTIVE 事件。相机服务历史显示 10-31 00:21:37 CONNECT device 0 for fans.lty.app (PID5084)，00:21:52 断开；本次确实使用物理相机而非 v137_1138。此前同一包曾连接 v126_1127。进程内上下文复用是待验方向，不宣称已确定根因。

## 代码修正

1. 把窗口转场能力从读取当前主题后直接带入规则准入；明确不支持转场时，不选择已有 scene 档案，也不先改背景再执行注定失败的 Scene。目标是阻止支付宝这类机制主动结束页面的路径。
2. 提供直接读取 SurfaceFlinger 协议的层级快照后备路径，不依赖应用调试接口能否返回 primitive getter。当前窗口实际 UID、View 哈希、Surface 完整名字、父链和相对窗口图层都必须匹配；两次快照的层级与身份一致后才采用，且需要系统实际具备 setCompositionOrder。未知层级继续拒绝，不猜默认 -2。
3. 当前设备的 SurfaceFlinger 协议中存在不合法的厂商图层记录（例如悬浮图标条目），独立坏条目必须丢弃，不能破坏其他完整身份；选中图层或其父窗口不可完整解码时仍拒绝。
4. 加入公开 APK resources.arsc 的路径到资源 ID 索引，支持改名后的 res/... 文件、稀疏/16位索引和紧凑条目。不载入应用 Java 代码；候选资源仍要在当前 Resources 中解析为同一路径、同一 Drawable 类，歧义时拒绝。背景主题匹配仍不是完整 Drawable 状态快照，保留 themeResource 证据等级。
5. 去除对单个厂商“来自资源”字段的硬性依赖；当前真实 Drawable 类可来自结构或 DUMP。仍不按机型、ROM、版本白名单准入。
6. Getter 不可用时保存具体回包原因；主题资源解析失败记录主题值，避免只有 resource=false 无法定位。
7. 新增可选 Start-Phone-VDimension-Cold.cmd：由用户自行运行，显式结束 V次元当前进程后重新启动，不清除应用数据。只用于检验物理/虚拟相机路由，可能结束未保存页面；不会由自动 Alpha 机制悄悄强停。即使相机路由恢复，共享整页 Surface 的 Alpha 分离仍未验证。

## 验证边界

读取了设备相机服务历史、一个图层协议快照，以及支付宝/向日葵公开资源表；未打开或点击用户应用。电脑离线解析、身份拒绝和构建检查不等同于四应用兼容已通过。实际页面测试继续由用户进行。

源码依据：AOSP SurfaceFlinger layers.proto 的 ID、z、parent、z_order_relative_of、owner_uid；AOSP ResourceTypes.h 的资源表、字符串池、type/entry 与 compact/sparse/offset16 定义。解析失败和歧义都回退，不带不完整证据去改属性。


另修复恢复守卫的重复结束：restoreScope 只是持有恢复身份，释放时必须 close(false)，不能因为释放守卫就再次 finishOriginal。E13 支付宝日志中出现两次 closed_original_child_activity，与此重复路径一致；新版本不会在未应用属性的构造失败中因为释放守卫而结束页面。

离线实际数据：图层协议快照可完整采用 223 个有效图层条目；支付宝资源表解析出 844 个 res/ 文件路径，向日葵为 3887 个。另验证匹配必须同时满足 UID、View 哈希、相对窗口、父链，且重复/不相关候选必须拒绝。此结果仅证明解析与匹配有效，不证明对应扫码已透明。
