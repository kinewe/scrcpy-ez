## 可直接补的规则与仍需验证的规则

1. **已改：候选必须是叶节点。** TextureView/SurfaceView 本身不是 ViewGroup；有子 View 的 ReactSurfaceView 不能仅因后缀相同就当相机。Steam 的真正预览位于更深处，选错容器会把控件也当作相机。此改动只排除结构上不成立的候选，不宣称 Steam 已恢复透明。
2. **待验：类名是线索，不是类型证明。** 可结合实际继承能力、View 哈希与所属窗口/UID 的 Surface 图层验证混淆子类；但 V次元这样全页共享渲染器不能直接整层设透明，应分别标记“相机已触发”“有渲染表面”“有独立相机区域”。这不是包名白名单问题。
3. **待验：使用变换后的可见相机区域。** Steam 的 SurfaceView 原始尺寸 1920×1080，scaleX≈0.75、scaleY≈2.37037，实际覆盖约 1440×2560，还受父容器裁剪。向日葵也有超出窗口的预览。不能把本地宽高直接用作全局 Alpha 检查区域；需累计父链矩阵并与裁剪区域求交。
4. **待验：恢复能力独立判定。** Steam/向日葵在根 Activity 内扫码，不能沿用“结束扫描子 Activity 恢复”的策略。应优先研究精确原始 Surface composition order、可恢复 Drawable 来源或无需改背景的捕获路径。未证明可逆前继续拒绝，不能简单绕过检查或关闭整个应用。
5. **待验：根窗口与 display 不必精确相等。** 历史失败记录出现 3202×1440、1440×3206 等尺寸；初始横置和 flex 对齐可能令严格全屏比较失效。应验证真实窗口坐标、insets、裁剪和来源，不能只是放宽阈值。
6. **已改：保存可行动的场景失败原因。** 原先档案只留 system_scene_IOException，无法区分功能缺失、回调失败或图层失败。新候选保留受限格式的具体错误码；本轮不重新触发支付宝转换，因此旧错误仍标为待复测。
7. **待验：区分初始透明与持续稳定。** 米游社/抖音说明初始两帧通过不代表缓冲会持续清理。应更早识别源端 Alpha 累积，记录稳定性证据，已知成功路径可直接复用。不能靠覆盖率暂时降低就立即关闭页面。

本轮没有为五个应用伪造成功规则或写入新的 supported 档案。已有米游社成功档案是用户之前实验产生的历史证据；机型、版本、尺寸仅作观察记录。

## 横置原因与修复

GUI 的 `nativeRes` 为传输档案归一成横向，普通应用窗口又通过它换算默认 WxH；主屏物理参数缓存来自 wm size，记录的是自然方向，也不能代表当前旋转。因此“默认采用设备比例”实际常变成横置，旧代码仅对少数应用做方向补丁。

新候选默认传递“启动方向跟随主屏”意图，由手机服务在每次创建虚拟屏时读取当前主屏逻辑宽高，调整初始宽高方向；不在 GUI 线程新增同步 ADB 查询、不使用长 TTL 缓存推断当前方向。显式设置 W:H 的用户配置优先，有线/无线各自选择；不改变主屏旋转或锁定应用后续旋转。此修复针对启动时横竖形态，不是强制镜像物理显示屏的所有旋转状态。

已通过桌面端纯逻辑测试（当前横/竖逻辑尺寸、手机/平板、方形、像素预算不变）、GUI/传输参数测试和构建。遵守本轮只读边界，未启动新版到设备上做方向实机验证。

## 当前实现与边界

Engine 12 候选仅包含：叶节点过滤、具体场景错误码、默认初始方向修复。未实现通用 Drawable 快照恢复、共享 Flutter/GL 内部相机分离或新的纯色回退。三处桌面送帧核心保持不变。下一轮优先解决根 Activity 的精确恢复，再采支付宝的具体转换失败；V次元共享表面需单独论证，不能为“识别成功”牺牲全部 UI。

## Engine 15 后续（2026-10-31）

用户复测 Engine 14：支付宝已不再退出，四个应用仍显示纯蓝底。Steam 的扫码页会自行暂停相机预览，并显示点击恢复提示；此时仍在同一页面，不能把相机 Surface 的消失直接归类为应用不兼容。

### 已核实的读取缺口

默认 `dumpsys SurfaceFlinger --proto` 原始数据没有 Steam 虚拟屏窗口的名称字节，解码后也没有目标层。此前“解析器丢弃 Steam 记录”的说法不成立；默认协议快照过滤虚拟显示才是这次层级后备失效的原因。

改用系统 Perfetto 的 `android.surfaceflinger.layers`，配置 `MODE_DUMP`、`TRACE_FLAG_VIRTUAL_DISPLAYS` 与 `TRACE_FLAG_EXTRA`，已通过纯 shell 在当前手机取得单次快照。实际记录包含 UID 10360 的 Steam 窗口，以及原始 z=-2、relative 指向同 UID 应用窗口、parent 经 Bounds 返回该窗口的相机 Surface。其 View 哈希为 931048e，层 ID 55432；这些仅是本次现场值，不进入可移植规则。

生产读取通过标准输入传入短配置，通过独立标准输出接收二进制，丢弃命令的诊断输出；没有安装 APK，不注入应用代码，不开启持续跟踪。解析器支持 Perfetto TracePacket 的字段 93 和旧 LYRTRACE 两种封装。系统不支持该快照时回退旧协议，仍必须取得两次一致且身份完整的目标层才能使用原始层级。

### 新候选路径及边界

新增 `window-direct`：在根 View 尺寸/位置与虚拟屏一致、现有属性可恢复、系统具备同步窗口事务与句柄能力时，借用精确应用窗口的 SurfaceControl，直接读取窗口图层。该分支不启动设置页面，不触发场景透明转换；无效时仍按能力判断是否使用已有 system-scene。每个相机实例有界尝试，失败恢复属性并停留，不反复重试，不将它写为成功。该分支的实际 Alpha 兼容性尚待用户测试，不能视为已修复支付宝等应用。

直接窗口档案必须来自 Engine 15，包含 prepareWindowSource、window-buffer-layer，以及 exact 或有现场证据的 themeResource 恢复策略；不接受 closeScanner 或系统场景元数据。继续由至少两帧原生 A8、空间变化、相机区域透明覆盖检查决定成功，成功后才入档。

主题读取增加容量、独立超时及错误日志，避免把读取失败当作主题没有资源。运行中预览消失记录为 camera_preview_disappeared，不生成“不支持”档案；恢复预览后重新匹配实际 View。

V次元 Engine 14 日志已经有虚拟相机活动与送帧，问题是单个共享渲染 Surface 下的 Alpha 分离。当前未添加隐藏整块共享 UI 的规则，不能宣称已兼容。

## Engine 15 现场失败与 Engine 16 收敛（2026-10-31）

Engine 15 的 Steam 实测已完成：两次快照稳定读到实际 SurfaceView 的 z=-2，绑定使用 exact 恢复；直接窗口借用句柄也成功。但 display-mirror、window-direct、system-scene 均未通过原生 Alpha 验证，SUPPORTED 为 0，不能宣称已修复蓝底。

该轮还暴露生命周期缺陷：在 exact 恢复模式下，system-scene 失败后释放整个会话，下一次轮询又对仍存在的同一窗口重试，导致重复场景转换与相机重建。用户已按要求关闭测试窗口。Engine 16 改为恢复属性、仅释放可恢复的窗口/场景句柄，保留 suspended 会话，等待实际页面或预览变化；不因同一失败状态立即重跑补救。同时新增每个失败阶段的 min/max Alpha、透明像素数、相机区域覆盖和实际来源日志。

原始结构中 Steam 的祖先含 CompositeBackgroundDrawable，虽然 drawing:opaque=false，仍不能据此证明相机区域是透明的；它只是非全不透明属性，保留的不透明区域和原生窗口状态都仍需分辨。这是下一步调查线索，不是已证明的根因。本轮没有尝试不可恢复地清除自定义 Drawable，也没有隐藏带有其他 UI 的祖先。

Engine 16 保留已证实的虚拟屏图层读取修复与有界直接窗口候选，仍未验证 Steam Alpha 成功。用户暂时无需再轮测其他应用。


### Engine 16 现场结果（同日）

用户从 RC23_E16_STEAM 进入扫一扫后，日志 RC23_E16_STEAM-17732.log 记录：

- display=163，SurfaceView 原始层级已命中，恢复策略 exact。
- display-mirror、window-direct、system-scene 三阶段均为 minAlpha=255、maxAlpha=255、partial=0、samples=4608000、cameraAlphaCoverage=0，SUPPORTED=0。直接窗口和场景窗口句柄均取得成功，仍然不透明。
- system-scene 仅执行一次，失败后恢复 opacity 并保存一条 unsupported；到约 31 秒后预览消失，没有再次触发场景转换。与 Engine 15 的重复转换问题相比，现场验证已收敛。

因此 Steam 的自暂停确实缩短取证窗口，但不能解释全部蓝底：相机活动期间已读到完整不透明 A8。下一步需区分根背景、自定义 React 背景绘制和窗口合成标志，不应继续通过延长采样或重复场景转换碰运气。当前仍不得写入成功档案。
