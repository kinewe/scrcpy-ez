# RC.17 layout6：自由窗口与原设备 UI 实验

版本仍为 `2.4.2-rc.17`，FileVersion `2.4.2.1706`，客户端/server 协议 `5.0.1-ez2.4.2-rc.17-layout6`。

## 测试目标

用户已确认：Pad 8 Pro 浏览器在原 thaw5 开启“窗口跟随”时变成底部导航样式，关闭后恢复顶部标签与地址栏。layout6 保留 flex，并尝试避免窗口缩小带来的 Android 显示密度变化。原生尺寸与密度来自 Android 当前主显示屏的有效参数，不依赖 GUI 的 Physical density 缓存。

本模式自动用于普通应用窗口的“窗口跟随开启 + 界面密度自动”。手动指定 DPI、关闭窗口跟随、透视相机和既有微信通知原屏兼容路径保持各自行为。

Android 虚拟屏按窗口长宽比重新生成逻辑画布，短边尽量保持主屏短边像素数、DPI 保持主屏有效值；视频独立缩放到电脑窗口需要的尺寸并服从编码限制。同长宽比下反复缩小、放大电脑窗口，原则上只改变视频输出尺寸，不改变应用看到的逻辑画布。改变长宽比仍允许内容重新排版。

这只能尽量保留原设备的 UI 类型，不能强制所有第三方应用保持同一布局，也不能保证任意长宽比下控件位置不变。逻辑画布限制为单边 8192、总像素 20 Mi；极端窄长比例达到上限时保持比例并降低逻辑空间，日志会标记 `native_short_edge=false`。应用自身对方向、可用宽度或显示 ID 的判断仍可能切换布局。该渲染路径的真实设备效果待用户测试，本地回归与编译不能替代实测。

## 用户操作

1. 退出旧 EZ，在本目录运行 `Start-Flex-UI-Test.cmd`。原 thaw5 目录和日志保留。
2. 选择同一平板和浏览器，在应用窗口设置中确认“窗口跟随”开启、DPI 为自动。复制的旧档案可能保留上轮关闭 flex 的设置，需要在本测试包内打开。
3. 打开原页面，依次缩小、放大、拖成竖向和横向，检查顶部标签栏、地址栏、文字、滚动、页面边缘点击是否正常。缩小窗口后再放大，观察是否恢复及是否有明显跳变。
4. 正常关窗，提供本目录 `app-flex-ui-test.log`，并说明是否保持原 UI。息屏状态也可一并观察，设备操作均由用户进行。

## 日志与回退

- `SCRCPY_EZ_FLEX_UI action=enabled`：实际主屏尺寸和有效 DPI。
- `action=prepare`：电脑请求尺寸、Android 逻辑尺寸、实际视频输出尺寸、DPI 和逻辑短边是否保留。
- `SCRCPY_EZ_APP_LAYOUT`：主屏/虚拟屏回读，以及目标 root task 的 densityDpi、width/height/smallestWidth dp、screenLayout、方向；root task 不是浏览器内部的资源判断日志。
- 保留 thaw5 的进程冻结、输入和白名单恢复诊断。省电名单、目标包解冻与 30 秒心跳回收逻辑未修改。

若需对照旧自动 DPI 行为，可在启动本测试包前设置 `SCEZ_VD_PRESERVE_UI=0`；运行代码会跳过 layout6 策略，仍保留旧 flex 路径。默认脚本不强制覆盖该环境变量。无需改主屏 `wm size/density`，也不重启或强停浏览器。

本地测试覆盖逻辑画布、编码尺寸、旋转、输入映射和分配边界；实际结果见随包 TEST_REPORT.md。调查前置证据见源码 `docs/rc17-app-window-layout-investigation.md`。
