## 已确认

- 去除原生 Alpha 路径的应用、机型、版本及 ROM 固定准入名单。通过当前预览结构、框架/组件能力、恢复范围、实际场景协议和两帧真实透明输出判定。

## 性能与用户观察

| 环节 | 旧实现 | 新实现实机初期均值 |
|---|---:|---:|
| 软件复制 | 约 24–26 ms | 使用可读 GPU 输出缓冲 |
| getPixels + Java 转换 | 约 58–64 ms | 保留预乘像素，省略该往返 |
| 编码 | 整页约 47–55 ms | 变化行约 8–12 ms |
| 新画面速率 | 约 6–8 FPS | 通常约 22–28 FPS |

短时 GPU/编码基准单帧约 35–51 ms；这是分段基准，不应当作电脑端显示速率。实际接通日志记录设备编码和电脑接收速率；窗口的 UI 帧率统计真正的纹理更新。8 分钟左右的运行接收了 11,099 个有效帧、没有补丁校验错误；237 个速率采样窗口的中位为 22.9 FPS，最高 28.3 FPS，最低 9.8 FPS，仍存在偶发下降。用户确认“明显更流畅，叠加正常”。旧窗口显示的 50+ 是原视频相关计数，不是原生 UI 新画面速率。

## 自动检查

- Java 编码器与生产 C 解码器跨语言验证：80 帧、16 个完整帧、64 个补丁，逐字节比较 2,363,200 个 RGBA 字节；覆盖 epoch、尺寸变化、CRC 错误、错误补丁、完整帧恢复。
- D3D11 实际纹理输出检查：2048 个像素逐通道核对，覆盖直通与预乘输入、微弱 Alpha、几何失配、失效来源。
- Go 档案、合并、策略记录等测试：52 项通过。
- Android 实机判定自检通过；41 个发行文件哈希与版本、旧探针缺失、RC22 清洁及三个送帧核心文件不变检查通过。最终回访结果由 test-results 中本轮日志记录。
