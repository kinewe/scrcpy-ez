# RC23 能力匹配与原生 Alpha 加速原型

本包以 RC22 的 `6f63b8ec4438ce554c9aa446cebf540499b827fd` 为基底，在独立 RC23 工作区构建。无需 root、不安装 APK；设备端使用 ADB shell 和现有服务 DEX。桌面采集、编码与向设备送帧的三个核心文件保持不变。

## 启动

正常使用运行本目录的 scrcpy-ez.exe，选择已连接设备及应用。不要混用旧目录的客户端或服务文件。手机/平板的 Start-*-WeChat.cmd 等为当前实验环境的快捷入口，其地址可以修改；这些地址不参与能力判断。首次安装与微信登录仍由用户完成。

当前独立目录为 `rc.23-native-alpha-auto-rules-win64/scrcpy-ez-2.4.2-rc.23`。旧包保留。本地 profiles.json、settings.json 与图标从旧包导入，发行 ZIP 不包含这些个人数据。

## 原生通道

先验证相机 View、窗口归属、可恢复操作与真实透明输出。需要系统场景过渡时，临时使用设备已有的系统设置页面，确认其组件、UID、目标任务和 display，完成过渡后结束自己创建的页面。没有桥接 APK，也没有向微信进程注入代码。

界面来自应用窗口缓冲层的 RGBA，不使用键色、背景反推或 PNG 与视频动态区混合。桌面背景仍沿用原有送帧流程。原生 UI 是独立的无损数据流。

### 本轮加速

旧实现每帧将硬件图像复制到软件 Bitmap、读取直通 RGBA、逐像素处理，再压缩整页。因此不生成 PNG 文件也仍然可能很慢。

本版使用 shell 自己的 HardwareRenderer 将已捕获的硬件图像以 SRC、无滤波、无抖动方式写入可读 RGBA ImageReader。首次使用和来源修订时，与同一图像的软件参考逐字节核对；不支持、非 sRGB 或校验异常时使用保留原 A8 的软件后备路径。

首帧发送整页预乘 RGBA，后续按变化行发送无损补丁。桌面端重建后校验整帧 CRC；没有有效基准、跨 epoch、内容错误等情况下丢弃补丁并请求完整帧。显示层直接使用预乘像素，避免再次乘 Alpha。没有降低分辨率、降低 Alpha 位数或对扫描光带做模糊。

合成生效时，左上角的 `UI …fps` 统计真正更新的原生 UI 纹理；原视频刷新率不再冒充扫描动画帧率。静态 UI 没有变化时，该数值可降低。

K80 微信 8.0.78、1440×3200 的本轮实测：旧通道约 6–8 FPS，新通道常见约 22–28 FPS（较长运行中位 22.9，偶有下降），用户确认更流畅且叠加正常。这个结果不能外推为所有应用/设备都达到同一帧率。整个页面持续大幅变化时会回到整页编码，速度可能下降。

能力与档案详见 [AUTO_ALPHA_PROFILES.md](RC23_AUTO_ALPHA_PROFILES.md)，证据与验证边界见 [CAPABILITY_REPORT.md](RC23_CAPABILITY_REPORT.md)。

## 规则与高效读取更新（engine 9）

参见 RULES_DESIGN.md。规则身份排除设备/版本诊断信息，支持 P3 等输入自动选择 GPU 到 sRGB 读取。A8 必须完全一致；色域转换的 RGB 与软件参考允许最多 1 个色阶差，不再把转换后的颜色称为原始 RGBA 逐字节不变。异常时回退并最多重试两次；sRGB 软件后备直接复制预乘像素，省略 Java RGB 往返。stream 字段记录选择、证据及单段性能样本，不表示该设备永远达到该帧率。

Windows 界面操作与应用内导航由用户完成。快速测试可双击 Start-Tablet-WeCom.cmd、Start-Tablet-XHS.cmd、Start-Phone-QQ.cmd 等；一次只保留一个待测窗口。


## 2026-10-30 Engine 11 补充实测

当前 auto-rules 包已加入 SurfaceView 的系统场景透明补救、持续异常确认以及长图层名称的 ID/UID 交叉匹配。抖音旧通道的动画累积会在原始页面缓冲出现；新路径直接读取应用窗口缓冲，用户已确认干净且正常停留，再进约 2.9 秒直接合成，超过五分钟未复现。成功规则自动入档，包名、机型和版本未加入新策略白名单。首次未知规则本例约 27 秒才触发补救，首次发现速度仍有改进空间；未测试应用与旋转不能据此判定兼容。进一步提帧研究按用户要求暂缓。详见 RULES_DESIGN.md / RC23_RULES_DESIGN.md。


## Engine 12 候选（2026-10-30）

本包新增默认应用窗口启动时读取主屏当前逻辑宽高方向；明确设置的比例优先，后续仍允许应用旋转。传输档案横向归一尺寸不再用于判断当前方向。结构规则新增候选叶节点要求，避免 ReactSurfaceView 容器被当相机；失败档案保留更具体的场景错误码。五个失败应用的只读结构报告在源码 docs/handoffs/结果_失败应用结构探测_20261030.md。尚未完成它们的透明兼容修复；本轮遵守只读要求，未推送新 DEX 或测试新规则的属性修改，方向修复也尚待正常启动实机确认。


## Engine 13 实际规则候选

已实现根背景资源清除与资源恢复、原始 Surface order 能力快照、根 Activity 可逆恢复分支、变换后的相机区域、有限对齐差、持续退化提前补救，以及共享整页 UI 拒绝。详细实现与测试重点见 docs/handoffs/变更_Engine13_原生透明规则候选.md。themeResource 是主题资源/类型匹配的候选恢复，不能宣称运行时 Drawable 状态完全一致。设备实测由用户进行，未把这些应用标为已兼容。


Engine 13 测试入口：Start-Phone-Alipay.cmd、Start-Phone-Mihoyo.cmd、Start-Phone-Steam.cmd、Start-Phone-Sunlogin.cmd、Start-Phone-VDimension.cmd。它们只是方便本次手机测试的入口，不是规则白名单。关闭旧窗口再运行，每次只开一个；日志保存在 logs/RC23_E13_应用名-随机数.log。请同时看首次进入、返回再进、退出投屏后的背景恢复。
